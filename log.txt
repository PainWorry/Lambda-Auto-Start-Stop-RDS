[LOG-004]
Timestamp: 2026-10-11 09:29:12 +07:00
Component: Terraform CLI Installation (Linux Mint)
Problem: "terraform: command not found" when trying to run terraform commands.
Root Cause: Cache setup commands (mkdir plugin-cache, export TF_PLUGIN_CACHE_DIR) were executed before installing the Terraform binary itself. Additionally, Linux Mint uses codename "zena" which causes HashiCorp's official APT repository to return 404 (HashiCorp uses Ubuntu codename "noble").
Solution: Downloaded and installed the official 64-bit standalone Terraform binary directly into /usr/local/bin:
  cd /tmp
  wget https://releases.hashicorp.com/terraform/1.9.8/terraform_1.9.8_linux_amd64.zip
  unzip -o terraform_1.9.8_linux_amd64.zip
  sudo mv terraform /usr/local/bin/

[LOG-006]
Timestamp: 2026-10-11 09:38:27 +07:00
Component: Terraform State & Dependency Locks
Problem: "Error: Inconsistent dependency lock file. Required by this configuration but no version is selected."
Root Cause: Ran "terraform plan" before initializing the provider plugins. Terraform requires an initial dependency resolution step to download the provider plugins and lock their versions in .terraform.lock.hcl.
Solution: Run "terraform init" inside the terraform directory before running plan or apply:
  terraform init

[LOG-007]
Timestamp: 2026-10-11 09:51:00 +07:00
Component: Terraform AWS Provider (S3 Lifecycle Configuration)
Problem: "Warning: Invalid Attribute Combination ... No attribute specified when one (and only one) of [rule[0].filter,rule[0].prefix] is required."
Root Cause: In AWS Provider v5+, aws_s3_bucket_lifecycle_configuration requires an explicit filter {} block inside rule {} when targeting all objects in the bucket, otherwise it triggers a deprecation warning.
Solution: Added an empty "filter {}" block inside rule {} in terraform/main.tf.

[LOG-008]
Timestamp: 2026-10-11 09:53:30 +07:00
Component: Terraform CLI (Plan Artifacts)
Problem: User queried where the generated "tfplan" file is located and how to inspect its contents.
Root Cause: The "-out=tfplan" flag creates a binary ZIP archive in the current directory that cannot be read directly via plain text editors (cat/nano).
Solution: The file is located at terraform/tfplan. Inspect its contents using HashiCorp CLI commands:
  terraform show tfplan          # Human-readable format
  terraform show -json tfplan    # Structured JSON format

[LOG-009]
Timestamp: 2026-10-11 10:02:45 +07:00
Component: AWS RDS (PostgreSQL Engine Version Deprecation)
Problem: "Error: creating RDS DB Instance (cloudops-governance-dev-db): operation error RDS: CreateDBInstance ... api error InvalidParameterCombination: Cannot find version 15.7 for postgres"
Root Cause: AWS periodically deprecates older patch releases of database engines. In ap-southeast-1, PostgreSQL 15.7 was deprecated and retired from orderable RDS versions in favor of newer patch releases (e.g. 15.13+).
Solution: Queried active versions via "aws rds describe-orderable-db-instance-options --engine postgres --db-instance-class db.t3.micro" and updated "engine_version = '15.13'" in terraform/main.tf.

Component: Git & Security Governance (Excluding tfplan)
Problem: Inquiry regarding whether the "tfplan" file should be tracked and added to Git ("git add tfplan").
